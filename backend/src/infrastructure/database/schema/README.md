# database-schema.json

Reference schema that `scripts/verify-schema.ts` (`npm run db:verify`) compares the
live database against: the 11 tables the Node backend uses, all InnoDB — the 10
tables imported into DigitalOcean from Zeabur (`docs/change/NewData報告.md`) plus
`contact_idempotency_keys` (migration 008).

`db:verify` checks, per table in this file: the table exists, its engine, every
column's existence / `DATA_TYPE` / nullability / `AUTO_INCREMENT`, and every index
(including `PRIMARY`) — existence, uniqueness and column order. Tables that exist
in the database but not here (e.g. legacy Laravel tables in an older local DB) are
ignored.

It was generated by read-only `information_schema` introspection of a blank
`mysql:8.4` database after `npm run db:migrate` (001–008). For the 10 tables that
also exist in `docs/change/NewData.sql`, every column and index matched the
introspection of that import exactly. `category` / `used_by_apis` were carried
over from the previous snapshot.

This file no longer equals `specs/backend/migration-history/database-schema.json`.
That one is the historical snapshot of the Zeabur production schema (25 tables,
mixed MyISAM/InnoDB, 2026-07-21) and is kept unchanged as a record.

A database restored from NewData.sql reports `contact_idempotency_keys` as missing
until `npm run db:migrate` applies 008 to it.

When a migration changes the schema, update this file in the same change and make
sure `npm run db:verify` passes against a database built by `npm run db:migrate`.
